# 第 5 课实践：把一次体验变成可恢复的记录

这一课把“做完一次占卜”升级成可长期使用的个人流程：保存完整会话、查看历史、导出备份并安全恢复，同时保证坏文件不会伤害现有数据。

## 课程目标

- 首次成功解读后保存完整会话；
- 使用 S5 打开历史列表、详情和备份工具；
- 导出可迁移的版本化数据；
- 恢复前校验结构，并以合并方式处理已有记录；
- 追问更新同一条历史，不产生重复会话；
- 恢复失败时保留当前历史和当前牌局。

## 当时基线

第 4 课的会话能够恢复问题、锁定牌局、首次解读和追问，但主要服务当前浏览器会话。第 5 课增加 IndexedDB 长期历史和用户主动控制的数据迁移。

## 范围与禁止事项

本课不把私人占卜自动上传到云端，不让导入文件覆盖当前牌局，不提前做趋势推断，也不把“已经写入 IndexedDB”直接当成用户可恢复的证据。

## 实现思路

1. 给历史记录定义独立版本和稳定身份，避免同一会话重复保存。
2. 只有首次解读成功后才产生长期记录，未完成牌局不污染历史。
3. 导出包含完整必要字段；导入先解析、验证、去重，再合并。
4. 历史工具与主牌局状态隔离，打开和关闭工具不改变锁定结果。
5. 所有数据默认留在浏览器本地，跨设备迁移由用户主动执行。

## 关键转折与踩坑

- **保存不是备份**：IndexedDB 只在当前浏览器来源中有效，必须提供下载和恢复才形成迁移闭环。
- **恢复不是覆盖**：错误文件、未知版本或缺字段记录应被拒绝，现有历史不能因此清空。
- **追问属于原会话**：如果每条追问都新增历史，会破坏一次占卜的完整上下文。
- **工具状态必须独立**：S5 打开备份界面时，主牌局仍然是只读且锁定的。

## 人与 AI 如何分工

- 人决定哪些数据值得长期保存、迁移行为是否可接受，以及隐私边界。
- AI 帮助设计版本化结构、导入校验、去重规则和失败测试。
- 用户通过真实下载、清空隔离环境和恢复操作证明备份确实可用。

## 验收证据

| 层级 | 本课证据 |
|---|---|
| 数据结构 | 历史记录拥有版本、稳定身份和完整会话字段 |
| 自动测试 | 覆盖保存、重复追问、导出、恢复、合并和坏文件拒绝 |
| 浏览器 | 在隔离来源中完成真实导出与恢复，当前牌局保持不变 |
| 隐私 | 默认本地保存，只有用户主动下载或选择文件时发生迁移 |

详细时间线见 [`QA.md`](../../QA.md)。

## 读者练习

1. 完成两次解读并打开历史，确认每次会话只出现一条。
2. 为第一条记录增加追问，确认列表数量不增加。
3. 下载备份，在另一个浏览器来源中恢复。
4. 尝试导入普通文本文件，确认错误可见且现有历史不变。

## 当前版本中的变化

历史后来成为第 7 课周期洞察的数据源，但原始记录仍保持只读。当前版本增加更多界面入口和 S8 返回路径，没有改变“用户主动迁移、失败不破坏数据”的原则。
