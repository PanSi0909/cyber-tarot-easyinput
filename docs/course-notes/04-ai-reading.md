# 第 4 课实践：让 AI 解读服从锁定的牌局

这一课的核心不是调用一个模型，而是建立一条安全的内容生成管线：输入必须来自已确认事实，失败可以重试，但不能改变问题、卡牌、位置或正逆位。

## 课程目标

- 读取已确认的问题、牌阵、位置、卡牌和正逆位；
- 生成逐牌解读、整体流动、结论、行动建议和语音简版；
- 保存首次结果并支持同一会话中的连续追问；
- AI 失败时允许重试解读，但绝不重新抽牌；
- 没有安全服务端配置时使用明确标记的 mock。

## 当时基线

第 3 课已经建立语音问题、四种牌阵、抽牌锁定和刷新恢复。第 4 课从这个稳定会话继续工作，不重写语音输入或抽牌状态机。

## 范围与禁止事项

本课不修改已验收的 S1–S3 核心流程，不实现历史统计，不把 API 密钥写入前端或 Git，不让模型补造卡牌事实，也不因生成失败改变当前牌局。

## 实现思路

1. 从锁定会话构造结构化输入，模型看不到未确认草稿。
2. 把塔罗知识、提示词、Provider 和页面展示分开，便于独立测试。
3. 先用确定性 mock 验证交互和数据结构，再保留服务端真实 Provider 接口。
4. 首次解读与追问共享会话身份；追问沿用原牌局，不制造新抽牌。
5. 缓存成功结果；失败状态只影响生成面板，不回写核心会话。

## 关键转折与踩坑

- **“有 AI 文案”不等于“接入真实 AI”**：页面必须显示 Provider 和 mock 标识，避免把模拟结果包装成模型输出。
- **专业感来自输入合同**：先固定牌面线索、基础牌义、问题语境和位置关系，再讨论文案风格。
- **逆位不是正位反义词**：用阻滞、内化、延迟、过量或条件未成熟解释，减少机械翻转。
- **恢复后的追问必须回到原会话**：刷新恢复不仅要显示旧文字，还要恢复正确输入目标和上下文。

## 人与 AI 如何分工

- 人定义什么是可信输入、哪些说法不能出现，以及 mock 与真实模型的公开边界。
- AI 帮助把知识和提示词结构化、补充失败测试、实现 Provider 抽象。
- 服务端负责保管密钥；前端只发送经过验证的结构化数据。

## 验收证据

| 层级 | 本课证据 |
|---|---|
| 源码 | 知识模块、提示词、Provider、解读与追问会话进入版本历史 |
| 自动测试 | 覆盖输入只能读取锁定事实、失败不改牌局、追问沿用会话 |
| 浏览器 | 首次解读、失败重试、追问和刷新恢复形成闭环 |
| 服务边界 | 默认 mock 零费用；真实密钥仅允许位于服务端环境变量 |

详细时间线见 [`QA.md`](../../QA.md)。

## 读者练习

1. 在同一牌局中提出两条追问，确认卡牌和正逆位没有变化。
2. 断开本地服务端或制造一次生成失败，确认可以重试而不重抽。
3. 在浏览器开发者工具中检查静态资源，确认不存在真实 API 密钥。
4. 用自己的话解释为什么 mock 也有价值、又为什么必须明确标记。

## 当前版本中的变化

当前版本保留服务端真实 Provider 骨架，但 GitHub Pages 固定运行本地 mock。后续课程把首次解读写入历史，并基于历史产生学习和洞察功能；这些不是第 4 课原始范围。
