# 第 8 课实践：把八个功能整合成一个产品

结课阶段没有继续堆大型功能，而是统一八键、旋钮、鼠标和普通键盘的入口，解决模式冲突、长按重复、错误焦点和安全返回，让前七课能力形成可连续演示的闭环。

## 课程目标

- 固定 S1–S8 的职责并保留键鼠备用输入；
- 所有入口进入统一动作函数；
- 当前活动模式独占旋钮和确认动作；
- 长按期间忽略重复 `keydown`，松开后才允许下一次；
- S8 每次只返回当前层级，不删除锁定牌局和历史；
- 完成自动测试、浏览器回归、真机验收和交付材料。

## 当时基线

第 3–7 课已经分别实现语音问题、综合解读、历史、学习模式和周期洞察，但多个模式共存后，同一个输入可能被重复处理，返回路径也缺少统一规则。

## 范围与禁止事项

本课以整合和验证为主，不重新设计主界面，不重写稳定数据结构，不修改固件或 EasyInput 键位，不用隐藏错误来通过验收，也不把 mock 描述成真实 AI。

## 实现思路

1. 固定 S1 开始、S2 牌阵、S3 输入、S4 解读、S5 历史、S6 学习、S7 洞察、S8 返回。
2. 鼠标、主键盘、小键盘、固定文字和旋钮统一转换为业务动作。
3. 输入优先级为：S8 安全返回 → 周期洞察 → 学习模式 → 历史工具 → 主占卜流程。
4. 每个模式只处理属于自己的动作，处理后停止传播。
5. S8 执行最小返回：关闭详情、收起结果或取消未确认步骤，不清除已确认事实。
6. 用完整回归证明整合没有破坏前面课程的能力。

## 关键转折与踩坑

- **入口越多，越需要一个动作层**：分别监听键盘会导致同一次实体输入被多个模块处理。
- **返回键不是清空键**：S8 只回退临时层级，锁定问题、牌局、解读和历史都在保护范围内。
- **长按不是多次意图**：浏览器重复事件必须由按下集合去重。
- **页面可见不等于可操作**：结果浮层曾遮挡顶部返回入口，需要从层级关系解决。
- **收起不等于销毁**：重新按 S4 应显示同一份解读，而不是再次生成或丢失追问。

## 人与 AI 如何分工

- 人判断产品是否完整、操作是否自然，并决定最终交付边界。
- AI 帮助建立动作优先级、补回归测试、定位交互冲突和整理材料。
- 实体开发板、浏览器和 CI 分别验证不同层级，任何单一证据都不代表整个产品成功。

## 验收证据

| 层级 | 本课证据 |
|---|---|
| 自动测试 | 八键映射、模式优先级、长按去重、S8 回退和页面合同进入完整回归 |
| 浏览器 | 主流程、追问、历史、学习、洞察、返回、刷新和窄屏布局完成检查 |
| 实体硬件 | S1–S8、旋钮、语音、模式切换和一次输入一次动作通过真机验收 |
| 交付 | 键位表、演示脚本、边界说明和 QA 证据形成可复查材料 |

结课清单见 [`COURSE-8-DELIVERY.md`](../../COURSE-8-DELIVERY.md)，详细时间线见 [`QA.md`](../../QA.md)。

## 读者练习

1. 分别从学习、历史和洞察详情中按 S8，记录每次只返回哪一层。
2. 在同一页面长按数字键，确认动作只发生一次。
3. 收起综合解读再用 S4 打开，确认内容和追问没有重生成。
4. 不连接开发板，用鼠标和普通键盘完成全流程，说明硬件优化了什么。

## 当前版本中的变化

结课后继续完成 V2 牌面生产、长内容旋钮浏览和正逆位视觉修正，但统一动作、输入优先级和 S8 安全返回仍是当前架构。公开仓库后来增加 GitHub Pages、课程案例和本学习中心。
