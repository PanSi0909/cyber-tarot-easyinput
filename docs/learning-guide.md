# 第 2–8 课学习路线

这个仓库不是把每节课机械拼在一起，而是记录一条从底层证据到产品体验的渐进路线。

| 阶段 | 实践产出 | 主要学习目标 |
|---|---|---|
| 第 2 课 | Host Action v1 复刻 | 读懂工程、冻结协议、测试驱动、USB/BLE 接入、构建、烧录与真机验证 |
| 第 3 课 | S1–S3 启动、牌阵和语音问题 | 把硬件输入转成稳定、可观察的网页动作 |
| 第 4 课 | S4 综合解读和追问 | 分离前端状态、结构化 AI 输入、服务端密钥和失败重试 |
| 第 5 课 | S5 历史备份 | 使用 IndexedDB 保存完整会话，并安全导出、恢复和合并 |
| 第 6 课 | S6 学习模式与 78 张牌面 | 设计独立模式、原创视觉资产和旋钮浏览长内容 |
| 第 7 课 | S7 周期洞察 | 从历史生成可追溯统计，样本不足时诚实降级 |
| 第 8 课 | S8 返回与整体收口 | 统一输入优先级、回退规则、回归测试和作品交付 |

## 第 2 课：AI 硬件的 12 步

完整源码与记录位于 [`case-studies/easyinput-host-action-v1/`](../case-studies/easyinput-host-action-v1/README.md)。十二步可以压缩为四道证据门：

1. **读懂与基线**：确认工程、板型和现有测试是真的。
2. **协议与实现**：先冻结设备与 App 的合同，再用宿主测试实现纯逻辑。
3. **通道与构建**：区分逻辑正确、USB/BLE 接通和固件能够生成。
4. **写入与验证**：由人确认目标设备和写入范围，最后观察真实结果。

最重要的不是记住命令，而是始终区分六类证据：源码阅读、宿主测试、固件构建、烧录、App 同步回执和真人观察。

## 第 3–8 课：从输入到产品

网站阶段始终保持三个原则：

- 一个硬件输入在当前上下文中只执行一个动作；
- 已确认的问题、抽牌和历史不能被“返回”或失败重试意外覆盖；
- 没有真实模型、硬件或历史证据时，界面必须明确降级，而不是伪造成功。

详细课程交付见 [`COURSE-8-DELIVERY.md`](../COURSE-8-DELIVERY.md)，逐项验证见 [`QA.md`](../QA.md)。

## 推荐阅读顺序

1. 先在 GitHub Pages 用鼠标或普通键盘体验完整流程。
2. 阅读 [`architecture.md`](architecture.md)，理解硬件、App、系统和网页的职责边界。
3. 阅读 Host Action 案例 README 和 12 步总结。
4. 只运行宿主测试，理解“无需开发板也能验证”的纯逻辑部分。
5. 准备好 ESP-IDF 5.5.5 后再构建固件；不要把构建成功当成真机成功。
6. 只有明确确认目标设备后才考虑烧录。
