## 第 2 课：AI 硬件的 12 步

十二步可以压缩为四道证据门：

1. **读懂与基线**：确认工程、板型和现有测试是真的。
2. **协议与实现**：先冻结设备与 App 的合同，再用宿主测试实现纯逻辑。
3. **通道与构建**：区分逻辑正确、USB/BLE 接通和固件能够生成。
4. **写入与验证**：由人确认目标设备和写入范围，最后观察真实结果。

最重要的不是记住命令，而是区分源码阅读、宿主测试、固件构建、烧录、App 回执和真人观察这六种强度不同的证据。

## 第 3–8 课：从输入到产品

六篇实践章使用同一结构，方便对照阅读：目标、基线、范围、实现、转折、分工、证据、练习、当前变化和相关资料。它们来自真实协作记录，但关键对话已经脱敏和编辑，不是聊天全文。

网站阶段始终保持三个原则：

- 一个输入在当前上下文中只执行一个动作；
- 已确认的问题、抽牌和历史不能被返回或失败重试意外覆盖；
- 没有真实模型、硬件或历史证据时，界面必须明确降级，不能伪造成功。

## 推荐阅读顺序

1. 按[新手实操指南](getting-started.md)完成在线体验。
2. 阅读[系统架构](architecture.md)，理解固件、App、系统和网页的职责边界。
3. 阅读第 3–8 课实践章，观察功能如何逐步生长。
4. 用 Git 提交链接查看每课的真实变化，而不是只读最终总结。
5. 需要证据时再查 [`QA.md`](../QA.md)；需要演示脚本时查 [`COURSE-8-DELIVERY.md`](../COURSE-8-DELIVERY.md)。
6. 有固件开发需求时再进入第 2 课案例；只有明确确认目标设备后才考虑烧录。
