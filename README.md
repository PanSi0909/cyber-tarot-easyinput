- S7 固定文字“周期洞察”、Digit7、Numpad7 和顶部鼠标/触摸按钮统一调用 `performAction('insights')`。再次触发 S7 关闭浮层；旋钮左右在 7 / 30 / 365 天间循环，短按只确认当前范围一次。
- 洞察生成后，旋钮自动改为左转向上、右转向下浏览长内容；短按返回时间范围选择。生成按钮作为鼠标/触控备用入口保留，但不再显示为硬件主流程。
- “历史备份”和“周期洞察”作为相邻的档案工具放在顶部导航，功能仍彼此独立；页面入口移除 S5/S6/S7 徽标，键位说明集中保留在使用手册。
- 数据源只读第 5 课的 `cyber-tarot-history` IndexedDB。时间字段使用 `createdAt`，窗口为“当前时刻减去 N × 24 小时”到当前时刻，起止边界都计入，未来记录排除。
- 本地统计包括记录数量、常见牌阵、重复卡牌、正逆位数量和比例、问题发生的时段及星期分布。重复卡牌定义为在所选记录的全部抽牌中出现至少 2 次的同一稳定卡牌 ID；牌阵按历史记录中的 `spread.id` 聚合。
- 少于 3 条有效历史时显示“数据不足”，仍可展示客观计数，但不会调用 AI、不会生成或暗示趋势，并明确说明还需要多少条记录。
- AI 只接收版本化统计摘要和最多 20 条可追溯摘录，不接收或改写原始历史对象；输出固定为主要主题、重复模式、可能的关注点、反思问题和可执行建议，并附“仅用于自我反思，不是确定性预测或专业意见”边界。
- 周期洞察以 `cyber-tarot-insight-v1` 独立保存在 `cyber-tarot-insights` IndexedDB；来源字段只引用历史 ID，报告另存生成时的统计摘要快照。失败可由用户重试；失败、重试和保存均不写回 `cyber-tarot-history`。
- 页面默认使用零成本 `mock-insight-local-v1`，原解读继续使用 `mock-local-v3`。访问 `?provider=api` 时才经 `/api/insights` 进入既有安全服务端；真实密钥仍只允许从服务端环境变量读取，服务端不自动重试。

## 本地启动

零成本页面模式：在此目录运行 `python3 -m http.server 4173 --bind 127.0.0.1 --directory dist`，打开 http://127.0.0.1:4173/ 。

本地服务端模式：运行 `node server.mjs`，再打开 `http://127.0.0.1:4173/?provider=api`。默认 `TAROT_AI_PROVIDER=mock`，请求仍由本地专业知识模拟接口完成，不访问外部模型、不产生模型费用。两种模式都必须通过 HTTP 打开，不能直接双击 HTML。

私有正式站点：https://cyber-tarot-between-signals.a0921093504.chatgpt.site/ 。线上仍为已验收的第 7 课 V1.5.1，访问范围继续保持仅所有者可访问；当前 `main` 的第 8 课 V1.6.0 尚未发布。实体 S1–S8 与旋钮流程已在当前版本通过真机复验。

## 第 5 课历史与流程

- 首次综合解读成功后，完整会话自动保存到浏览器 IndexedDB；新增追问时更新同一条记录，不重复创建会话。当前标签页的即时恢复仍沿用 `sessionStorage`，长期历史与当前会话职责分开。
- 每条 `cyber-tarot-history-v1` 记录包含稳定 ID、创建/更新时间、问题、牌组、牌阵、按顺序排列的卡牌、位置、正逆位、AI 结构与知识版本、provider、首次完整解读及全部追问。
- 历史列表可打开单条详情，查看问题、牌组、牌阵、卡牌、完整 AI 解读、语音简版和追问。
- S5 固定文字“历史备份”打开或关闭备份工具；旋钮在“保存历史备份”和“从备份恢复”之间切换，短按确认。综合解读全屏显示时，S5 会暂时收起结果浮层并定位到备份工具；再次按 S5 返回原解读滚动位置。鼠标和触摸按钮保留为备用入口。
- “保存历史备份”把全部历史下载为一个文件，适合在清理浏览器数据、换浏览器或换设备前留存；“从备份恢复”把文件中的记录与当前历史合并，不会先清空现有记录。
- 备份文件内部使用带 `cyber-tarot-history-export-v1` 版本标识的 JSON；页面只在说明中解释它是电脑读取的数据文件，用户无需打开或编辑。恢复时先校验版本与完整字段，再按记录 ID 合并，同一 ID 保留更新时间较新的版本。
- 页面明确显示“正在加载 / 正在保存 / 已保存 / 失败”，加载、自动保存和恢复保存失败均提供对应重试入口；失败不会改变当前牌局。
- 这些版本化字段由第 7 课周期洞察只读聚合；原记录结构、内容和合并规则保持不变。

## 第 4 课 AI 解读

- 只有用户已经确认问题且牌阵完成后，才允许生成综合解读。接口输入只包含锁定的问题、牌阵、每张牌的位置及正逆位。
- 每轮洗牌时同时固定 78 张牌的正逆位；揭牌、刷新、生成失败重试和追问只读取现有结果，不再随机，也不重新抽牌。
- 综合解读按总览、逐牌三层解读、完整能量流动、核心矛盾、条件性走向、综合结论、行动建议和语音简版返回。牌面只作为反思框架，不替代现实判断或专业建议。
- 牌阵完成后，Easy Input S4 固定文字“综合解读”会直接进入并生成综合解读；进入该模式后旋钮左转向上、右转向下浏览长内容。
- 综合解读生成后，S3 会把系统语音转写目标切换到追问框，短按旋钮发送；抽牌前的 S3 仍只服务于原问题，两个阶段不冲突。
- 首次成功结果保存在当前标签页 `sessionStorage`，同一牌阵不会重复覆盖；刷新后连同追问记录恢复。开始新一轮时才清除。
- 追问会携带当前锁定牌阵、首次解读和本轮既有问答；最多保留最近 20 条。追问不会改变原问题、牌面、位置或正逆位。
- 单牌与综合解读共用 `dist/tarot-knowledge.mjs`：78 张牌都有可编辑的 RWS 视觉线索；22 张大牌逐张维护，56 张小牌按花色领域、数字/宫廷阶段和具体画面组合。正位、逆位、牌阵位置、重复位阶、主导花色和大牌比例都会进入解读。
- 默认 provider 为 `mock-local-v3`，页面明确显示“视觉线索模拟接口 · 零模型费用”。接口失败时显示重试入口；重试只重新请求解读。
- `server.mjs` 提供 `/api/readings` 本地代理；真实模型密钥只读取服务端环境变量。禁止把 API 密钥、Authorization token 或供应商私密配置写入 `dist/` 或 Git。
- 需要真实模型时，复制 `.env.example` 为不会提交的 `.env.local`，填入百炼工作空间地址和密钥，再用 `node --env-file=.env.local server.mjs` 启动并访问 `?provider=api`。当前低成本默认模型是 `qwen3.7-flash`，实际调用按供应商当期规则计费；本仓库不会自动开通、充值或发起真实调用。
- 真实服务端请求设置 30 秒超时、严格 JSON 结构校验，且不做自动重试，避免一次用户操作产生重复模型费用。
- 本课依据课件“一键启动我的内容创作工作台”的分层方式，将第 3 课输入与触发层保持不动，把 AI 路由/执行和会话资产独立封装。

### 模型选择与费用边界

- 开发和交互验收继续使用本地模拟接口，完全不调用外部模型；它适合验证字段、状态与硬件流程，不代表真实模型的语言上限。
- 首次小规模真实测试建议使用 `qwen3.7-flash`：成本低、支持结构化 JSON，且当前服务端已经完成百炼兼容接入。需要更细腻的叙事时，可用同一批固定牌局 A/B 测试 `qwen3.7-plus`，而不是先重写前端。
- DeepSeek、豆包可作为后续服务端 A/B 选项，但不能复用网页聊天页面或非官方免费通道。正式供他人访问时必须使用供应商官方 API、服务端密钥、预算告警、速率限制和内容安全能力。
- 所谓免费通常是新用户额度、限时赠送或体验模式，不应作为正式产品的长期成本模型。正式上线前先以固定测试集测量单次输入/输出 token，再按预计日调用量选择充值额度；不要一开始购买大额套餐。

## 第 3 课互动

- S1 直接开始，S2 直接进入牌阵选择。网页在后台兼容固定文字“开始”“牌阵选择”、旧称“牌组选择”和数字键 1 / 2，不再显示固定文字输入框。
- 待机、等待 S2 和结果阶段会自动维持后台硬件焦点；切回页面或点击空白处后无需再点输入框，固定文字与数字键均可继续触发。
- 用户首次按 S1、按兼容数字键 1 或点击“开始”时，网页在该次用户操作内立即调用浏览器语音合成，播放短句“欢迎回来。想好问题，我们开始吧。”同一标签页只尝试一次。
- 牌阵选择包含单卡指引、时间之流、命运抉择和凯尔特十字四种结构，分别抽取 1、3、5、10 张。旋钮左右切换，短按确认。
- 确认牌阵后才随机洗牌。网页只呈现当前牌附近的 7 张卡背，但旋钮可以循环到完整 78 张；已抽出的牌不会重复出现。
- Easy Input 的 S3 保持“语音输入”功能。它不是网页键盘事件，而是把系统转写文字写入当前焦点；因此 S2 完成后，S3 的文字会直接进入问题框。数字键 3 / 小键盘 3 仍可作为电脑键盘的“聚焦问题框”备用动作。
- 页面提供待机、正在聆听、已停止、等待确认和失败状态。浏览器 `SpeechRecognition` / `webkitSpeechRecognition` 只作为额外备用入口；不支持、无麦克风、权限被拒绝或识别失败时，S3 系统语音输入或普通文字输入仍可继续。
- 语音输入或识别结果只是草稿，可以查看和修改。短按旋钮（Enter）或点击“确认问题”后，问题才写入当前占卜会话；刷新会随牌组恢复，S1 开始新一轮时清除。
- 完整实体流程无需鼠标：S1 开始 → S2 进入牌阵 → 旋转并短按确认牌阵 → S3 说话 → 短按确认问题 → 旋转并逐张短按选牌 → S4 进入综合解读 → 旋钮上下浏览 → S3 追问并短按发送。完成解读后可按 S5 打开历史备份工具，用旋钮选择保存或恢复并短按确认；恢复时仍需在系统文件选择器中选定备份文件。再次按 S1 进入新一轮。
- 第 3 课基线不接真实 AI、不做历史统计；第 4 课仅在已锁定结果之后追加模拟 AI 流程。

2. 本课不操作 EasyInput App，不修改或同步开发板键位，不烧录、不复位、不修改固件。
3. 若要让实体键显示并发送上述固定文字，需要用户在 Easy Input 中自行确认配置；本分支只负责网页兼容，不代为改键。S3 保持现有“语音输入”，S4 设置为固定文字“综合解读”，S5 设置为固定文字“历史备份”。
4. 网页“输入验证”显示接收到的 code、有效次数、被忽略的重复事件。开启“仅测试输入”可以只测输入，不启动语音或推进抽卡。
5. 数字键 1–8 与小键盘 1–8 对应八键职责；Escape 等价于 S8，NumpadEnter 兼容旋钮短按。
6. 问题框有焦点时，Enter / NumpadEnter 用于确认问题；确认后相同按键逐张选牌。结果页会在后台等待 S1 的“开始”指令。

网页不能检测实际硬件连接，不能区分开发板与普通键盘。不显示虚假的“已连接”。按住输入忽略浏览器 repeat 和未释放的重复 keydown；真实固件若发送多组完整按下/松开，网页会如实计数，需要进一步定位。左右方向和一格几次由固件配置及真机决定。

## 抽卡规则

- “开始”进入本轮，“牌阵选择”打开四种牌阵；旋钮/方向键切换牌阵，短按确认后仅洗牌一次。
- 问题框有文字时，第一次回车/旋钮短按确认问题；之后旋转浏览随机牌组，短按逐张选牌，直到满足牌阵数量。
- 揭晓后抽中的牌与顺序锁定；按 S4 前左右旋钮切换当前牌面说明，按 S4 后改为上下滚动综合解读，均不改变牌阵。“开始”会清除本次问题和结果并进入新一轮。
- 已确认问题与当前结果保存在本标签页 `sessionStorage`，刷新可恢复；V0.1 的五张示例牌会迁移到当前 78 张牌组。关掉标签页不作为长期保存。存储被禁用时页面明确提示。
- 开始新一轮无需鼠标或弹窗确认：在结果页再次按 S1 即可；页面按钮使用相同动作逻辑。
- 78 张卡牌结构、名称和分类按标准 Rider–Waite–Smith 体系整理；牌面为本项目程序化原创视觉，不复制参考站图片。正逆位在洗牌时一次性固定，AI 只读取锁定结果。
